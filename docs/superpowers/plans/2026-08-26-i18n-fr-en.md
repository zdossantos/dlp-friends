# Internationalisation française et anglaise Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fournir toute l’application en français et anglais avec une locale unique, détectée et persistée.

**Architecture:** Laravel résout la locale avant toute requête applicative, constitue les catalogues de messages et les partage avec Inertia. Vue lit exclusivement les props Inertia via `useTranslations()`. Un cookie porte le choix visiteur et `users.locale` celui du membre ; les intérêts utilisent `name_en` avec repli français.

**Tech Stack:** Laravel 13, PHP 8.4, Inertia 3, Vue 3 Composition API, TypeScript, Pest et Pest Browser.

**Spec:** `docs/superpowers/specs/2026-08-26-i18n-fr-en-design.md`

## Global Constraints

- Les seules locales supportées sont exactement `fr` et `en`; `fr` est la locale et le fallback Laravel.
- La priorité est `users.locale`, cookie explicite, `Accept-Language`, puis français.
- Les catégories d’intérêts ne sont ni traduites ni exposées ; seul `interests.name_en` est ajouté et son fallback est le nom français.
- Ne jamais traduire ou transmettre à un tiers les bios, noms d’affichage, messages ou autres contenus membres.
- Laravel est l’unique source des messages système; Vue ne contient ni catalogue ni règle de résolution de locale.
- Chaque changement de comportement suit rouge → vert → refactorisation et conserve les migrations nullables.
