# Audit Impeccable

## Méthode et niveau de preuve

Audit effectué sur `main` à `e2ddd76`, le 7 octobre 2026. Lecture des routes, pages Vue, composants partagés, documentation produit et design system. Les propositions répondent aux axes Impeccable de hiérarchie, cohérence, compréhension, accessibilité et finition. Le moteur `impeccable context` n’est pas installé ; les références du skill et du projet ont été lues directement.

Le serveur Laravel local n’était pas disponible. Les captures historiques de `artifacts/issue-185-189-theme-matrix/` ont servi de repères visuels ; elles utilisent des fixtures et précèdent des changements de navigation. Une image manquante ou un lorem ipsum dans ces captures ne prouve pas un bug actuel. Les constats ci-dessous distinguent le code actuel, les observations historiques et les propositions. Aucune prétention à un audit WCAG complet de production.

## Ordre de traitement

Valider d’abord la navigation mobile et les panneaux, puis les cartes/listes et formulaires, enfin les saisons et micro-interactions. Toute correction métier découverte pendant l’intégration relève d’un correctif séparé et de tests de régression, pas d’un changement silencieux du contrat produit.

## Ce qui est déjà utile et doit rester

Les primitives Reka et composants `ui/`, les tokens sémantiques, la navigation basse actuelle, les règles de localisation, les confirmations et les autorisations Laravel constituent le socle. Le prototype illustre un langage visuel commun ; il ne demande pas de reconstruire ces primitives ni de remplacer les routes.
